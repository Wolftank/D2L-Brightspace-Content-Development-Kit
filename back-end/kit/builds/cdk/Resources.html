Why we are strict about this

The habit exists for a reason

This project started with a confident and wrong belief: that a widget which read gradebook data was a SCORM object. It was not, and an entire architecture was nearly built on top of that. Everything since has been measured rather than assumed, and anything unmeasured is labelled.

Design systemOptional

makes it look like SCSU

The Husky Course Kit is a set of paste-ready HTML blocks in SCSU's visual language. These very pages are built with it. Using it is entirely optional, and nothing in the kit depends on it, but it is the difference between an activity that looks bolted on and one that looks like part of the course.

Download the design system scsu-d2l-design-system.zip · 48 KB

Open any .dc.html file in a browser to browse the blocks, keeping support.js beside them. Copy a block's HTML and paste it into your own page, or point Claude at the folder and say which file to take the look from. A README inside explains the two tiers and the palette.

It works in two tiers. Loud is ink and cardinal with hard diagonal wedges, for the few things that must be noticed: headers, dividers, the one warning that matters. Warm is cream cards with rounded corners and a softer voice, for everything explanatory. The triangle you keep seeing is the Husky peak, and it is what makes unrelated blocks read as one system.

One adaptation worth copying. The original kit pulls its fonts from Google. These pages name the same fonts but ship no external link, because campus network policy can block outside hosts and a blocked font should degrade rather than break the page. That is the same rule the gate enforces on your builds.

Synthetic studentsOptional

run a semester before anyone takes it

A corpus of 500 fictional students, built so an agent can play them. Point Claude at a course you have built, hand it a slice of these personas, and it can work through your material the way a real cohort would: submitting late, misreading instructions, skimming, over-writing, and in some cases cutting corners.

The point is to find out where a course breaks before students find out for you. It is also the easiest way to stress test something, since you can regenerate the corpus at any size.

The corpus in three formats, plus Python scripts to regenerate it at any size or with a different mix. Same seed gives byte-identical output, so a test run is reproducible.

The field you will actually use

agent_brief

Every student carries a self-contained, second-person paragraph covering who they are, how they write, how they use the LMS, and how they behave under pressure. Drop it straight into a prompt. For most simulation work you can ignore the structured fields entirely.

One design choice worth knowing about

Cheating is independent of demographics

Academic dishonesty is dealt across the corpus as a balanced, shuffled allocation rather than sampled per student, so it does not correlate with nationality, native language, English proficiency, age, major, or residency. The verification script enforces this with a tolerance check and fails the build if any group drifts.

This matters more than it might look. If you tuned or trained a detector against a corpus with an accidental correlation in it, you would be teaching it to flag international students. There is not one here, by construction.

Every student, name and ID is fabricated. IDs use a deliberately non-standard format so they cannot collide with real institutional ones, and nothing in the corpus is modelled on a real person.

Words you will run into

TermWhat it actually means
Content topic An HTML file you upload into the course that shows up as a page. Runs inside D2L, so it can tell who is looking at it.
SCORM package A zipped-up activity in a standard format that can put a score in the gradebook by itself. Runs in a sealed box, so it cannot see anything else about the course.
Origin The web address a piece of code is served from. Browsers use it to decide what that code is allowed to touch. This is why the three approaches differ.
The gate A command that checks your build against measured tenant behaviour. Zero errors and you can deploy.
Preview mode What D2L gives an instructor opening their own SCORM package. Looks normal, records nothing, reports no error.
Attempt One run at an activity by one student. Attempt limits and best-of-N are D2L settings, not something you build.
Skill A folder of written instructions Claude reads when the task matches. No installation, no service, no background process.

Getting help

  • Ask Claude, inside the kit folder. It has the skills, the tools and the evidence in front of it. Describe what you did and what you saw.
  • Test locally before you involve D2L. The emulator enforces our tenant's real behaviour on your own computer, so most problems surface without a single request to anyone.
  • Recruit a TA or colleague for the live check. For anything graded they need to be enrolled as a student, since instructor permissions only ever produce a preview.
  • Bring findings back. If you hit a D2L behaviour that is not in the kit, it should be measured and added, so nobody hits it twice.
