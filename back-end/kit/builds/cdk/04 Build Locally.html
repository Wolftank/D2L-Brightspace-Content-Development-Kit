Step Four

Build Locally

The rule that saves the most time

D2L is where finished things go

It is not where you build them. Every trip through D2L costs you an upload, a click path, and a wait, and it hides what went wrong. Build and check locally until it is genuinely finished, then deploy once.

The loop

minutes, not uploads

Starting the conversation

say what, not how

Describe the experience, not the technology. Claude will run the routing questions with you and pick the approach. If you name a technology up front you may skip the question that would have caught a mismatch.

Say something like

"I want students to drag the parts of a cell onto a diagram and get told what they got wrong. It should be worth 10 points and they can try three times."

That description contains everything the router needs: it is interactive rather than a quiz, it is graded automatically, and it needs attempts. You do not have to know that adds up to a SCORM package. That is the skill's job.

Or if you already ran step 2

"Step 2 said content topic. Build me a page that shows students the assignment brief and shows me the marking notes on the same page."

Seeing it

before D2L, always

Ask Claude to serve the folder and open it. Do not open the file directly from your file manager: a page opened that way cannot load its own data files, so it will look broken for a reason that has nothing to do with your build.

Say

"Serve this locally and show me what it looks like."

Then actually use it. Click every button. Answer wrongly on purpose. Reload the page halfway through and see whether it remembers. Most defects show up in the first two minutes of genuinely using the thing.

The gate

zero errors to ship

When it looks right, check it against the tenant. This catches the failures that are invisible in a local browser because they only happen inside D2L.

node harness/lint/lint.js <your-folder> --avenue scorm|topic|external

Every finding explains why, quoting the behaviour we measured. The point is that you learn the constraint, not just silence the check. Warnings are advisory; errors are things we watched break.

Or just

"Run the gate on this and fix anything it finds."

Worth knowing while you build

Do it first, not later

Name the file now

The file name becomes the topic title in D2L, and renaming a live topic silently corrupts it. Decide the exact wording students will see before anything is uploaded.

Especially for SCORM

Keep it short

The embedded player will not scroll a tall activity. Anything past roughly 600 pixels becomes unreachable. Design it to fit, or plan to open it in a new window.

A real limit

About 4000 characters of memory

That is all a SCORM package can save per student. Plenty for answers and progress. Not enough for anything essay-shaped.

Ask for it out loud

Make it work on a phone

A meaningful number of students will open this on a phone in a hallway. It is much cheaper to ask for that now than to retrofit it.
