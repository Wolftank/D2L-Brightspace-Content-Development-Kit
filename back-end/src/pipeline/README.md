# back-end/src/pipeline

The runner and the session service. The runner executes one turn at a time per project: it acquires a session from the session service, sends the instructor's message, writes each driver event to the database and pushes it to the event stream, stores the agent's message, and creates a build at turn end if the turn changed the output. The session service opens sessions in a project's workspace through the driver, keeps them while they are useful, and closes them on idle timeout. The QA gate, the pedagogy check, and deployment proposals are tools the agent calls during a turn, not steps here. Both components are specified in [`../../../docs/architecture.md`](../../../docs/architecture.md). Empty stub; not built yet.
